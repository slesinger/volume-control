# CLAUDE.md

ESP32 (Wemos Lolin32) knob that controls Neumann KH speakers (KH 120 II / KH 150) over IPv6 using the Sennheiser Sound Control (SSC) protocol, with a 240x240 ST7789 display and a KY-040 rotary encoder. Built with ESPHome + a custom C++ component. Integrates with Home Assistant via ESPHome API services.

See also: `README.md` (hardware, wiring, original requirements), `docs/ARCHITECTURE.md`, `docs/ISSUES.md` (known bugs / tech debt), `docs/ROADMAP.md` (planned features).

## Layout

- `volctrl/volume_control.yaml` – ESPHome config: pins, TFT_eSPI build flags, HA services, rotary encoder + button wiring to the component.
- `volctrl/time.yaml` – SNTP time package.
- `volctrl/custom_components/vol_ctrl/` – the component:
  - `vol_ctrl.cpp/.h` – `VolCtrl` class: loop, debounced encoder ISR, button handling, HA entry points, group volume sync.
  - `menu.cpp` – data-driven on-device menu, speaker Param EQ / info pages.
  - `network.cpp/.h` – lwIP socket client for SSC (port 45) on its own FreeRTOS task: polling, coalesced writes, detail queries.
  - `wiim.cpp/.h` – WiiM HTTPS API on its own task (status, track metadata, commands, SSDP discovery).
  - `art.cpp/.h` – album-art download and JPEG decode (TJpg_Decoder) used as background.
  - `display.cpp/.h` – TFT_eSPI drawing, partial-region updates, background (`background.h` picture or album art), menu/text pages. `volume_font.h` is generated by `tools/gen_volume_font.py`.
  - `device_state.cpp/.h` – per-speaker state with change-detecting setters.
  - `utils.cpp`, `utils/json.*`, `utils/datetime.*` – hand-rolled JSON extraction, time string.
- `docs/` – SSC protocol spec (md + pdf), display/module datasheets.
- `cad/` – FreeCAD case. `khtool/`, `pyssc/` are gitignored reference checkouts (not in repo).

## Build / run

```bash
cd volctrl
esphome compile volume_control.yaml   # verify changes build (always do this after C++ edits)
esphome run volume_control.yaml --device OTA   # flash over the air (no serial prompt) + logs
```
Needs `volctrl/secrets.yaml` (gitignored): `wifi_ssid`, `wifi_password`, `encryption_key`, `ota_password`. Never commit it or print its values.

## Conventions / gotchas

- Everything runs in ESPHome's cooperative main loop. **Never block for long in `loop()` or encoder/button callbacks** – the task watchdog resets the chip. Network I/O runs on worker tasks (`network.cpp`, `wiim.cpp`, `art.cpp`); the loop only consumes cached results.
- Namespaces: `esphome::vol_ctrl`, with sub-namespaces `network`, `display`, `utils`.
- Text is drawn transparent over the background (single-arg `setTextColor`); clear regions with `fill_bg`, never `fillRect(..., TFT_BLACK)`.
- Display: TFT_eSPI is configured entirely through `platformio_options.build_flags` in the yaml (no User_Setup.h). Panel has no CS pin and needs HW SPI mode 2. Fonts must be enabled via `-DLOAD_FONTn`.
- Speakers are currently hard-coded in `network::init()`; commands go to *all* speakers.
- SSC messages are JSON terminated by CRLF; volume is `audio.out.level` (0–120 dB), mute is `audio.out.mute`, standby is `device.standby.countdown`.
- The README mentions ESP8266/EEPROM in places – the actual target is ESP32 (use ESPHome `preferences`/NVS, not EEPROM).
- No automated tests exist. When touching `utils` parsing, consider adding host-side tests (see ROADMAP).

## Workflow guidance

- Prefer small, compile-verified changes; hardware can't be tested from here, so say explicitly when something is only compile-checked.
- Fix items from `docs/ISSUES.md` before piling on new menu features; tick them off in that file as they land.
- Keep UI updates partial (per-region) – full-screen redraws over SPI are visibly slow.
